# 共有ブレインの地図（雛形）

<!-- このファイルは「地図」です。100行以内に保ち、詳細は各フォルダへ逃がしてください。
     書き方の背景は docs/shared-brain.md、設計の根拠は docs/brain/second-brain-design.md を参照。 -->

この repo は、参加する Bot（と人）が共有する知識置き場です。
方針とルールの正は（ルール文書の場所を書く）で、ここには事実・決定・状態・学びを置きます。

## 読み方

- 作業の前にこの地図と `projects/now.md` を見て、関係するファイルだけを開く。全部を毎回読まない
- 判断の根拠にしたら、使ったファイル名を挙げる
- 載っていないことは「載っていない」と言い、推測で埋めない

## 置き場所

| 場所 | 中身 |
|---|---|
| `projects/now.md` | 現在の焦点。最優先で見る |
| `projects/` | プロジェクトごとの状態と次の一手。1プロジェクト1ファイル |
| `people/` | 人と Bot のカード（役割、渡し方）。1対象1ファイル |
| `notes/` | トピックごとの事実。1ファイル1トピック |
| `decisions.md` | 決定の記録（何を、なぜ）。新しいものが上 |
| `diary/` | 各 Bot の日記。1 Bot 1ファイル |
| `playbooks/` | 手順書。その仕事のときだけ開く |

## 4つの層

| 層 | この repo では | いつ読まれるか |
|---|---|---|
| 1. 地図 | このファイル（＋ `projects/now.md`） | 毎回。小さく保つ |
| 2. ルール | 方針はルール文書（複写しない）。フォルダごとの書き方は `.claude/rules/` | そのフォルダを読み書きするときだけ |
| 3. 手順 | `playbooks/` | その仕事のときだけ |
| 4. 日記 | `diary/` | 各 Bot が書き、まとめ役が昇格させる |

## 守らせたいことは機械で止める

- 地図の行数、ファイル名の形式、秘密情報らしき文字列、壊れた相対リンクを、チェックスクリプトと CI で確認する

- 書き込み：（権限を持つ者だけ。配下の Bot の追記は窓口経由）
