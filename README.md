# botsetup — 複数 Bot を協調させるための運用まとめ

複数の AI Bot（常駐エージェント、実装担当、収集担当、検証担当など）を、GitHub リポジトリ経由で協調させて仕事を進めるための運用ノウハウをまとめた公開リポジトリです。

中身は2つです。

## 1. 共有ブレイン（secondbrain）— Bot 群の「第二の脳」

Bot が増えると、知識と文脈が各 Bot の中に閉じて、同じ説明と確認が何度も繰り返されます。それを避けるため、知識を「必要なときだけ読み込まれる層」に分けて置く共有リポジトリの設計です。

- 地図（毎回読む・小さく保つ）
- ルール（フォルダごとに、その場所を触るときだけ読む）
- 手順（その仕事のときだけ開く）
- 日記（各 Bot が書き、全体に効く学びだけを上の層へ昇格させる）

設計の要点と、文章だけでは守られないルールを機械チェックで止める話は [docs/shared-brain.md](docs/shared-brain.md) にあります。

## 2. Muse × Grok リサーチ活用術 — 調べものを「依頼」として設計する

検索担当（X 上の情報を探す Grok 側）と、司令塔（整理・比較・裏取りをする Muse 側）を分けたリサーチの進め方です。元は X 上の利用報告を集めた記事で紹介された20の活用法を、要点と依頼の型に要約し、私たちの運用への適用状況を付けました。

- 候補は大量に出させず「読むべき数件」に絞る
- 速報と確定情報を分け、情報の出どころを残す
- 取れた数字だけを比べ、取れない値は推測で埋めない
- 前回との差分だけを読む定点観測にする
- 利用枠と停止条件を最初に決める

詳細は [docs/research-playbook.md](docs/research-playbook.md) にあります。

## 3. 検索基盤とリポジトリ

- 検索基盤の使い分け（通常の Web 検索は自前ホストのメタ検索、X の投稿は Grok 側の x_search）は [docs/search.md](docs/search.md) にあります
- 使っているリポジトリの一覧と中身（調整と台帳／共有ブレイン／公開まとめ）は [docs/repositories.md](docs/repositories.md) にあります
- アプリケーションに意図的に入れる表現技術（three.js、シェーダ、状態と見た目の対応づけ、描画予算）は [docs/visual-tech.md](docs/visual-tech.md) にあります
- 他のアプリケーションへの適応のしかた（原則／型／中身の切り分けと適応手順、「作る前に探す」導入前チェック）は [docs/adaptation.md](docs/adaptation.md) にあります
- 単一システムの内部で複数のワーカーが動く構成への考慮（委譲の型、内部と外部の使い分け）は [docs/internal-multi-agent.md](docs/internal-multi-agent.md) にあります

どちらの設計も、単一の AI だけでも読み替えて使えます（各ドキュメント内の「単一の AI だけで使う場合」を参照）。

## すぐ始める（雛形）

前提知識なしで回し始められるよう、コピーして使える雛形を [templates/](templates/) に置いてあります。

- [templates/REQUEST.md](templates/REQUEST.md)：依頼ファイルの雛形（目的・入力・出力形式・禁止事項）
- [templates/RESULT.md](templates/RESULT.md)：返却ファイルの雛形（結論・詳細・不明／未確認）
- [templates/BRAIN.md](templates/BRAIN.md)：共有ブレインの「地図」の雛形
- [templates/bots.json](templates/bots.json) / [templates/requests.json](templates/requests.json)：台帳の最小例

組み立て方は [docs/adaptation.md](docs/adaptation.md) の「最小構成」と「適応の手順」を参照してください。

## 運用の全体像

```text
持ち主（方針と最終判断）
  │
  ├─ 常駐エージェント（受け口・割り振り・検証・台帳）
  │     ├─ 実装担当（コードを書く）
  │     ├─ 収集担当の窓口（配下の収集・意匠 Bot を振り分け）
  │     └─ 検証担当（マルチモーダルな独立検証）
  │
  └─ 共有ブレイン（全 Bot が読み、決まった権限の Bot だけが書く）
```

- 受け渡しは非同期・ファイル経由：依頼（requests/）→ 返却（inbox/）→ 検証済み（outbox/）
- 金銭・公開・アカウント操作・削除は、常に持ち主の承認ゲート
- 作る側と検証する側を分け、検証する側に答えを先回りして渡さない（検証の独立性）
- 新しいものは、作る前に既存で足りないかを一度確認する（導入前チェック）。持ち主がアプリや「こうしたい」を口にした時点で常駐がまず GitHub 等で既存を探しに行き、判断は記録に残す

## 注意

- このリポジトリは「やり方」の公開です。実際の運用データ、認証情報、個人情報は含みません。
- 活用術の出典は X 上の利用報告です。料金・無料枠・対応プランなどの数字は投稿者の記載であり、全員に同じ条件が適用されることを示すものではありません。各サービスの契約画面で確認してください。
- Grok Build（CLI から X 検索を呼ぶ経路）と Grok Bot（複数の Bot や定期実行を含む運用の仕組み）は別物です。片方を入れれば、もう片方の全機能が手に入るわけではありません。
