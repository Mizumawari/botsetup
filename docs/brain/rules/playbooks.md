# playbooks/ の書き方

手順書。繰り返す仕事の手順だけを置く。事実や決定は書かない（それぞれ `notes/` と `decisions.md`）。

## 形

```
# 手順: <仕事の名前>

いつ使うか: <きっかけ>。誰が: <担当>。

1. 手順（1行1動作。判断が要る分岐は「〜なら」と条件を書く）
2. ...

守ること: 承認ゲート、秘密情報、検証の独立性など、その仕事で外してはいけないこと。
最終更新: YYYY-MM-DD
```

## 決まり

- 先頭に「いつ使うか」を書く。読む Bot がこの1行で開くかどうかを決める
- 不可逆な操作（金銭・公開・アカウント操作・削除）は、手順の中で必ず みずまわり の承認を挟む
- 手順の中の分岐が「振り分け・分類・スコア・進行可否」なら、判定レイヤー（`playbooks/decision-gate.md`）を使う形で書く
- 手順と実際のやり方がずれたら手順を直し、「最終更新」を更新する
- 長くなったら（目安 30 手順）、仕事を分けて別ファイルにする
