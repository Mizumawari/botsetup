# 共有ブレインの設計の根拠（4層）

出典: 記事「Claude Second Brain 2.0: The Complete Guide」（@mojeskoqq）を 2026-11-03 に読んで整理。
Claude Code の仕様に関する記述は記事が公式ドキュメントから引いたもので、このワークスペースでの実測ではない。版で変わりうる（要再確認）。

## 4層と読み込まれる時期（記事による、Claude Code の場合）

| 層 | Claude Code での実体 | 読み込まれる時期 | この repo での読み替え |
|---|---|---|---|
| 地図 | `CLAUDE.md` | 毎セッション | `BRAIN.md`（`CLAUDE.md` から取り込み） |
| ルール | `.claude/rules/`（`paths:` 付き） | 該当ファイルを触ったときだけ | `.claude/rules/`（フォルダごとの書き方） |
| 手順 | skills | 呼ばれたとき、関係すると判断されたとき | `playbooks/`（`.claude/skills/` から呼べる） |
| 日記 | 自動メモリ（auto memory） | 毎セッション（先頭 200 行 / 25KB まで） | `diary/`（全 Bot に見える形で残す） |

- 原則: 知識は「必要なときだけ読み込まれる層」に置く。地図を小さく、中身を大きく保てる

## 記事が指摘する誤解と、この repo での対策

- `CLAUDE.md` はシステムプロンプトの一部ではなく、その後に「利用者の発言」として渡される。厳密に守られる保証はない
- メモリのファイルは「参考情報」であって「強制される設定」ではない。必ず守らせたいことは文章ではなく仕組みで止める
  （Claude Code では PreToolUse フック）
- → この repo では、守らせたいもの（地図の行数、ファイル名、秘密情報、リンク切れ）を `scripts/check-brain.sh` と GitHub Actions で機械的に確かめる

## 運用上の注意（記事による）

- `CLAUDE.md` は 200 行以内が目安。長いほど文脈を食い、守られにくくなる（この repo の地図は 100 行以内を目安にしている）
- `@` での取り込みは整理にはなるが節約にはならない。取り込んだ分も毎回読み込まれる。常に要るものだけ取り込む
- ブロックの HTML コメント `<!-- -->` は読み込み前に取り除かれるので、人間向けのメモを置いても文脈を食わない
- 長い会話の圧縮（/compact）のあと、チャットで伝えただけの指示は消える。ファイルに書いたものは読み直される
- 2つのファイルが食い違うと、どちらかが任意に選ばれうる。矛盾は週次の見直しで潰す（`../playbooks/weekly-review.md`）
- 1つの巨大なメモファイルにしない。1ファイル1トピック、小文字とハイフンの名前

## 健康診断に使える Claude Code のコマンド（記事による）

- `/context`: 実際に読み込まれたメモリファイルを確認する（Claude 系 Bot がこの repo で一度実行して、`CLAUDE.md` が載っているか確かめるとよい）
- `/memory`: メモリファイルの一覧と自動メモリの切り替え
- `/doctor prompt-audit`: 古い・壊れた・矛盾する指示を探す（記事では v2.1.283 以降）
