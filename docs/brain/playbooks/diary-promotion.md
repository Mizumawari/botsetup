# 手順: 日記の昇格（Muse の巡回）

いつ使うか: Muse の巡回（1時間ごと）で `diary/` に前回からの追記があったとき。誰が: Muse。

1. `git log` で前回の巡回以降に変わった `diary/` のファイルを洗い出し、新しい行だけを読む
2. 1行ずつ、bot-workspace の `docs/DECISION-GATE.md` §4 のカタログにある判定「日記の昇格」で行き先を決める（正本はカタログ。選択肢をここで増やさない）:
   - **Choice**: notes へ昇格 / decisions へ記録 / 日記に残す / 古いので破棄
   - state に渡す証拠: 追記の本文、日付、関係プロジェクト。下限未満なら Muse が読んで決める
   - 「古いので破棄」は昇格させないという意味で扱い、日記の行は消さない（削除は RULES §1 の承認ゲート）。末尾に「→ 昇格なし（古い）」と書き足す
   - 手順になりそうなもの（→ playbooks/）や人と Bot のカードの更新（→ people/）は、当面「notes へ昇格」として扱い、
     行き先を足すかはカタログへの追加提案として Muse が判断する（`playbooks/decision-gate.md` の手順8）
3. 方針の変更や承認ゲートに触れるものは昇格させず、承認センターかチャットで みずまわり に上げる
4. 昇格させるものは、行き先のルール（`.claude/rules/`）の形に整えて書く。日記の原文はそのまま残す
5. 日記の元の行の末尾に「→ notes/xxx.md」のように昇格先を書き足す
6. `decisions.md` への昇格は、Muse 自身の検証を経てから確定する（`playbooks/brain-write.md` の手順4）
7. 同じ種類の失敗が2つ以上の Bot の日記に出ていたら、`playbooks/` の手順か bot-workspace の RULES への追加を提案する

守ること: 日記を書いた Bot の言い分を勝手に書き換えない。昇格は「全体に効く形」への整形だけ。
