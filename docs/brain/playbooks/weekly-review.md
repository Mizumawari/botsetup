# 手順: 週次の見直し

いつ使うか: 週に一度、ブレイン全体の手入れをするとき（みずまわり か Muse に頼まれたとき、または Muse の決めた曜日）。誰が: Muse、または Muse が振った Claude 群。

1. `bash scripts/check-brain.sh` を実行し、エラーと警告を控える
2. `projects/` を全部読み、各ファイルについて次をまとめる:
   - この1週間で動いたこと
   - 止まっていること（「状態」の日付が14日より古いもの、待ち先が変わっていないもの）
   - 次の一手
3. `projects/now.md` が各プロジェクトのファイルと矛盾していないか確認する。終わった項目は外す
4. `people/` で「最終更新」が30日より古いカードを挙げる。役割や状態が変わっていないか本人（または管理）に確認する
5. ファイル同士の矛盾を探す（例: 同じことに違う数字や状態が書いてある、bot-workspace の RULES / PROTOCOL と食い違う）。
   見つけたら、どちらが正しいかを確かめて直し、理由を `decisions.md` に残す（RULES が勝つ）
6. `BRAIN.md` が肥大していないか見る（100 行以内）。手順や細則が紛れ込んでいたら `playbooks/` や `.claude/rules/` へ移す
7. この1週間に決まったこと（みずまわり の承認、Muse の採否、BOARD や依頼ファイルに書かれた決定）で、`decisions.md` に未記録のものがあれば、
   理由と出典（REQ 番号やファイル名）つきで追記する。`decisions.md` の変更なのでブランチと PR で出す（`playbooks/brain-write.md`）
8. 結果を `notes/weekly-review-YYYY-MM-DD.md` に書く（動いたこと / 止まっていること / 古いカード / 直した矛盾 / 記録した決定 / 次の一手）
9. みずまわり への報告は結論から、数字とリスク付きで短く

守ること: 見直しで新しい決定を作らない。記録するのは既に決まったことだけで、決定が要るものは みずまわり に上げる。
