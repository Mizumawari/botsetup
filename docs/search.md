# 検索基盤 — 何を、どのエンジンで探すか

調べものの質は、検索エンジンの使い分けでかなり決まります。私たちの運用で使っている検索基盤と、その分担です。

## 使い分け

| 探すもの | 使うもの | 備考 |
|---|---|---|
| 通常の Web 情報（第一手） | RustXNG（自前ホストのメタ検索） | 複数の検索エンジンの結果を束ねる。自分の環境に常駐させる |
| X の投稿 | Grok 側の x_search | X 内部の意味検索・ユーザー検索・スレッド取得。Web 検索では代替できない |
| 場所・店舗 | 場所検索サービス | 住所、営業時間、評価など構造化された情報 |
| 製品 | ショッピング検索 | 価格と在庫は変動するので、実店舗ページで再確認する |

## RustXNG（通常検索の第一手）

SearXNG 互換の、自前ホスト型メタ検索エンジンです。選んだ理由と、運用で効いた調整は次のとおりです。

- **自前ホストにする理由**: 全 Bot・全エージェントが同じ検索基盤を共有できる。ローカルのサービスとして常駐させ、誰のセッションからでも叩ける形にする
- **クエリの言語を明示する**: 日本語のクエリには言語指定（日本語）を必ず付ける。付けないと順位が崩れてノイズが増え、付けると公式ページが上位に来ることを実測した
- **エンジンは絞らない**: 束ねる検索エンジンは少数に curated すると性能が落ちる。既定のフルセットで使うのが前提
- **環境に合わせた調整**: 出口がプロキシ経由のみの環境では、プロキシ設定、証明書検証の扱い、タイムアウト延長、HTTP/2 の無効化などが必要になった。導入先のネットワーク条件に合わせて調整する項目として記録しておく
- **失敗したエンジンの扱い**: 一時的に失敗するエンジンは自動でしばらく外される設計なので、大量失敗の状態は時間をおくか再起動で解ける

## X の投稿は Web 検索では見つからない

- `site:x.com` のような Web 検索では、X の投稿はノイズが中心で、まともな発見にはならない（実測）
- X のミラーサイトは古い断片しか返さない
- X 内部の検索（意味検索で話題をたどる、特定ユーザーの発信を追う）は、Grok 側の x_search の領分として分担する

→ 調査の進め方は [research-playbook.md](research-playbook.md) を参照。

## 検索の運用ルール（共通）

- 検索結果は「手がかり」として扱い、判断に使う情報は元ページや公式情報で裏を取る
- 取れなかった情報は、もっともらしい値で埋めず「未確認」と残す
- 同じ検索を繰り返さない。結果は保存して再利用し、定点観測では前回との差分だけを見る
- 上限やエラーが出たら、その工程を未確認として止める（再試行を繰り返さない）
