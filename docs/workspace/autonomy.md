# 自律協調の設計（2026-11-02 みずまわり 承認済み。PROTOCOL の運用ルール）

目的: みずまわり が関与するのは「方針」と「承認ゲート（RULES.md）」だけにし、
それ以外の細部は Bot 同士の協調で自律的に進むようにする。

## 1. やり取りのベース

- **repo の状態が唯一の正**。会話やチャットで渡した内容は、repo に書かれるまで存在しないものとして扱う。
- やり取りの単位は3つだけ:
  - 依頼: `requests/REQ-*` ＋ `state/requests.json` の行（状態遷移が進捗そのもの）
  - 返却: `inbox/RES-*` → Muse が検証 → `outbox/`（検証済み）
  - 近況: `state/bots.json` の自分の行 ＋ `STATUS.md`
- 「Claude へ渡す内容は みずまわり に言うか repo に上げる」という みずまわり のルール（2026-11-02）はこの帰結:
  受け渡しは repo か みずまわり 経由のどちらかしか存在しない。

## 2. トリガー（何が誰を起こすか）

Bot は全員が常駐プロセスではない（Claude 群はセッション制、Grok 側は自前の巡回、Muse は cron 可）。
なので「push で全員が目覚める」設計にはせず、**状態変化＋巡回による差分検知**を基本トリガーにする。
トリガーの契約（ファイルと状態の意味）は固定し、検知の速さだけ後から上げる（巡回 → webhook / Routine）。

| 状態変化 | 起きる Bot | 動作 |
|---|---|---|
| requests.json に自分の担当で `open` の行が増えた | 担当 Bot（次回巡回/セッション開始時） | 着手し、状態を `working` にする |
| inbox/ に自分の依頼への RES が置かれた | Muse | 受け入れ検証 → 合格なら outbox/ へ、requests を `done`。不合格なら差し戻し REQ を発行（round を数える） |
| requests が `approval`（判断待ち）になった | Muse | みずまわり へ集約して報告する（1件ごとに騒がず、巡回ごとにまとめる） |
| bots.json に停止申告（blocked）や usage 枯渇が出た | Muse | みずまわり へ報告し、関連する依頼を止める |
| みずまわり が承認した（チャットでの返答 or repo への記録） | Muse | 記録して依頼を再開させる。みずまわり が repo を見に行く必要はない |

## 3. 巡回の担い手

- **Muse がハブとして定時巡回する**（例: 06:30–21:30 の間、1時間ごと）。
  repo の差分を見て、上の表の「Muse の動作」を実行し、判断待ちだけを みずまわり に出す。
  変化がなければ何も言わない。
- Claude 群: セッション開始時に必ず repo のキュー（自分の `open` / 差し戻し）を確認するのが起動手順。
  将来は Routine（定時 / GitHub 起動型）に置き換えて無人化する。
- Grok 側: 管理が自前の定時巡回で requests/ を見る（管理の申告どおり）。Muse 側からは催促しない。
- Gemini Spark: 登録済みで稼働中。同じ契約（自分の行とキューを見る）で接続している。

## 4. みずまわり の承認を「方針だけ」にする仕組み

- 個別の依頼は、**承認済みの方針（ロードマップや仕様）の範囲内なら Muse が発行してよい**。
  みずまわり の承認は方針の単位で一度だけ取る。範囲を出る依頼は発行前に みずまわり 行き。
- 承認ゲート（金銭・公開・アカウント操作・削除）は方針承認があっても個別に みずまわり 行き（RULES.md どおり）。
- 判断待ちは Muse が「選択肢＋推奨」を添えてまとめて出す。みずまわり の作業は選ぶことだけ。

## 5. 暴走防止

- 差し戻しは同一依頼で最大3 round。超えたら止めて みずまわり へ（無限の修正ループにしない）。
- Grok の利用量は bots.json の `usage` 申告が上限管理のベース。枯渇したら関連作業は自動で止まる。
- すべての受け渡しが repo に残るので、誰が何を根拠に進めたか後から追える（監査可能性）。
- 止めたいときは みずまわり がチャットで言うか、requests の状態を `blocked` にすれば全 Bot が止まる。

## 6. 段階

- フェーズA（現在）: 巡回は Muse の cron ＋各 Bot のセッション開始時確認。みずまわり の手起動が残るのは Claude 群のセッションだけ。
- フェーズB: Claude 群を Routine 化（定時または GitHub イベント起動）し、みずまわり の手起動をなくす。
- フェーズC: webhook で遅延を縮める（契約は変えない）。
