# RULES — 全員共通の規則

## 1. みずまわり の承認ゲート（最優先）

次の操作は、どの Bot も みずまわり の明示承認なしに行わない。

- お金が動く操作（購入、課金、契約）
- 外部への公開・送信（出品、投稿の公開、第三者へのメッセージ送信）
- アカウント操作（フォロー、いいね、登録変更）
- 削除（ファイル・データ・投稿の破壊的変更）

日常の調査・作成・検証はゲート対象外。迷ったらゲート側に倒して Muse に上げる。

## 2. 担当領域

- 各 Bot は REGISTRY.md に登録された自分の領域で動く。
- 他の Bot の主担当に入る前に、BOARD か STATUS で一声かける（「一番得意な者がやる」が原則で、領域は絶対ではない）。
- 同じファイルを同時に編集しない。着手前に BOARD で宣言する。
- コーディングは、読めて検証できる状態（差分が追える・台帳に残る・検証役が確認できる）に保てるなら、誰が書いてもよい（2026-11-02 みずまわり 確認）。これは Grok も同様で、Grok の担当も収集・意匠に限らない。メインのコーダーを Claude とするのは「得意だから」の目安であり、独占の指定ではない。

## 3. 検証の独立性

- 成果物の正しさは、作った本人ではなく検証役（原則 Muse、または別モデル）が担保する。
- 検証側の結論を先回りで潰さない。たとえば「答えはこれのはず」と実行側に渡すと独立した確認にならない。
  依頼には目的と形式だけを書き、答えの予想は書かない。
- 検証で使う物差し（測定条件・固定シード・判定基準）は依頼ファイルに明記し、全員で共有する。

## 4. 記録と形式

- 受け渡しは PROTOCOL.md の形式（requests/ → inbox/ → outbox/）を守る。
- 実在しない情報（URL・投稿・数値）を作らない。確認できないものは「不明」と書く。
- 数値には根拠（取得元・日時・条件）を付ける。推測は推測と明記する。
- 重要な決定とその理由は BOARD または依頼ファイルに残す。チャットの流れに埋もれさせない。

## 5. 秘密情報

- 認証情報（パスワード、API キー、トークン）はチャット・ファイル・リポジトリに書かない。
- みずまわり の一次資料（コーパス原文など「聖域」指定のもの）は読み取り専用。内容を Bot 間で転送しない。
- 依頼に含めてよいのは、作業に必要な最小限の情報だけ。

## 6. 停止条件

- 利用枠・レート制限に当たったら、それ以上の実行を止めて STATUS.md に申告する（再試行で粘らない）。
- 指示が矛盾する、入力が見つからない、想定外の状態に当たった場合も、推測で進めず止まって申告する。
- 同じ依頼の差し戻しが3 round を超えたら、実行側と検証側で繰り返さず みずまわり に上げる。

## 7. みずまわり への報告

- 報告は Muse がまとめて行う（結論から、数字とリスク付き、日本語）。
- 各 Bot は自分の成果を みずまわり に直接売り込まない。BOARD と inbox/ が公式の状態。
