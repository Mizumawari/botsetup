# 連携プロトコル

## 役割の基本形

| 担当 | 役割 |
|---|---|
| みずまわり | 方向づけと最終判断。承認ゲート（RULES.md）の通過は みずまわり のみ |
| Muse | 調整役。依頼の発行・割り振り、成果物の検証、記録（台帳・STATUS・BOARD の更新）、みずまわり への報告 |
| 各 Bot | 自分の担当領域の実行。収集・生成・実装など、REGISTRY.md に登録された得意分野で動く |

## 作業を始めるときの読み込み

各 Bot は、作業の着手前に次の順で読む（今までの読み込みに、共有ブレインを足したもの）。

1. `REGISTRY.md` / `RULES.md`（自分の役割と共通ルール）
2. 共有ブレイン（repo: Mizumawari/secondbrain）の `BRAIN.md`（地図）
3. その作業に関係するブレインのファイルだけ（`projects/`、`people/`、`notes/`、`playbooks/` から選ぶ。全部は読まない）
4. 自分の依頼ファイル（`requests/REQ-*.md`）

新しい学びや決定が出たら、ブレインへの書き込みは通常の受け渡しの流れに乗せる
（Grok 側は管理経由、実装側は RES に併記、Muse は巡回で diary を整理して昇格させる）。

## 受け渡しの流れ

1. **依頼**: Muse（または みずまわり）が `requests/REQ-<連番>-<名前>.md` を templates/REQUEST.md の形式で置く。
   依頼には目的、入力の場所、出力形式、禁止事項、期限の目安を必ず含める。
2. **着手**: 担当 Bot は BOARD.md（または Issue）の自分の行を「作業中」にし、STATUS.md に一行残す。
   dashboard/ や tools/ など複数の Bot が触りうる作業領域に入るときは、`python3 tools/claim.py claim <依頼ID> --bot <id> --paths <触る場所>`
   で着手を宣言して commit し、`git pull --rebase` の後 `python3 tools/claim.py verify --bot <id>` が通ってから push する。
   verify が失敗したら（後から宣言した側）push せず宣言を解放し、STATUS.md に申告する。返却時に `release` する。
3. **返却**: 成果物は `inbox/RES-<依頼ID>-<名前>.md` に templates/RESULT.md の形式で置く。
   生データ（raw）と要約は分ける。実在しない情報で埋めない。分からない点は「不明」と書く。
4. **検証**: Muse が検証する。観点は依頼ごとに異なるが、最低限「実在するか」「形式を満たすか」
   「依頼の範囲を超えていないか」。検証で落ちたものは理由付きで差し戻す（最大3 round まで。それ以上は みずまわり に上げる）。
5. **完了**: 検証を通ったものは `outbox/` に移し、BOARD を更新して みずまわり に報告する。

## 命名と ID

- 依頼 ID: `REQ-001`, `REQ-002` …（連番。プロジェクトを跨いで一意）
- 結果は依頼 ID に紐づける: `RES-REQ-001-<名前>.md`
- 日付は JST、`YYYY-MM-DD` 形式。

## 起動の引き金（自律度）

- フェーズA（開始時）: みずまわり または Muse が依頼ファイルを置き、担当 Bot は人が起動する。
- フェーズB（慣れたら）: GitHub イベント（push / Issue 作成）や定時 Routine で Bot が自分で起き、
  requests/ の新着を拾う。webhook を使う場合はキーをチャットに貼らない（安全な渡し方を みずまわり と決める）。

## 利用量の注意

- Grok 系（Bot / Cursor / アプリ）は利用枠が共有プール。重い生成や高頻度 Routine は枯渇の実績があるため、
  依頼には想定コスト（取得件数・生成回数）を書くこと。枠が逼迫したら新規着手を止め、STATUS.md に申告する。
- 他の Bot も同様に、自分のレート制限・上限に当たったら止めて申告する。当たった事実を隠さない。

## 自律協調（トリガーと巡回）

2026-11-02 に みずまわり が承認した運用。詳細は `docs/AUTONOMY.md`。

- やり取りのベースは repo の状態変化。トリガーは巡回による差分検知（将来 webhook / Routine に高速化しても契約は変えない）。
- Muse がハブとして定時巡回し、RES の検証・判断待ちの みずまわり への集約報告・停止申告の検知を行う。変化がなければ何も言わない。

- 差し戻しは同一依頼で最大3 round。超えたら止めて みずまわり へ。
