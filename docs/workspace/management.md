# 管理体制（全体像）

みずまわり の指示がどう割り振られ、誰が誰を管理し、結果がどう みずまわり に戻るかの一枚絵。
2026-11-02 に みずまわり が確認した形。詳細ルールは RULES.md / PROTOCOL.md / docs/AUTONOMY.md。

## 指揮系統

```
みずまわり（オーナー：方針と承認ゲートだけを決める）
│
└─ Muse（全体管理：指示の受け口、割り振り、検証、台帳、みずまわり への全体像報告）
   │
   ├─ 管理（Grok Bot 側の窓口：配下への振り分けと成果物回収、一次確認まで）
   │   ├─ テスト
   │   ├─ ゲーム開発アシスタント
   │   ├─ 各種データまとめ
   │   └─ トレード担当
   │   （Grok Bot 本体は独立した管理対象にしない。実務は配下: 意匠レビュー=ゲーム開発アシスタント、X 収集=各種データまとめ）
   │
   ├─ Claude 群（実装：セッションごとに担当を割り振る）
   │
   └─ Gemini Spark（登録済み・稼働中）
```

## 指示の流れ

1. みずまわり の指示は Muse が受ける（チャット）。みずまわり が各 Bot に直接指示を出す必要はない。
2. Muse が指示を依頼（REQ）に分解し、担当を割り振る:
   - 実装は Claude 群へ、X 収集と意匠は管理経由で Grok 側へ、検証と記録は Muse 自身。
   - Muse が抱えている仕事（自分のアプリの仕事を含む）も、割り振れるものは管理経由で Grok 側などへ出してよい（2026-11-02 みずまわり 許可）。ただし検証の独立性（RULES §3）と、Muse の内部でしか取れない情報・Muse の VM でしかできない作業は Muse に残る。
   - 割り振り先は repo の requests/ と BOARD に残る（誰に何を頼んだかが みずまわり からも見える）。
3. 成果物は inbox/ に返り、Muse が検証して outbox/ へ。管理側の配下の成果物は管理が回収して返す。
4. Muse が みずまわり に報告する。基本は結果だけ。判断が要るもの（方針・承認ゲート）だけ、
   選択肢と推奨を添えてまとめて上げる。

## 各管理者の責任

- **Muse**: 全体像の維持（この図と台帳）、割り振りの判断、検証の独立性、停止条件の監視、
  みずまわり への報告。Bot から みずまわり への確認事項はすべて Muse 経由。
- **管理**: Grok 側の内部の振り分けと回収、一次確認、利用量の申告（逼迫したら止めて申告）。
  Grok 側の内部で誰が何を担当したかは管理が把握し、聞かれたら答えられるようにする。
- **Claude 群**: 割り振られた実装の完遂と、着手・完了の申告（BOARD / bots.json の自分の行）。

## ダッシュボードの役割（この体制における位置づけ）

Bot オフィス（アプリ版を含む）は、この管理体制の可視化である:
誰が・誰から頼まれた何を・どの状態で進めているかと、みずまわり の判断待ちが溜まっていないかを、
みずまわり が一目で掴むための画面。操作はしない（読み取り専用）。
